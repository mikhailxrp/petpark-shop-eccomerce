# PHP Starter Template — SDD методология

Шаблон для быстрого старта PHP-проекта с готовой документацией и ядром приложения.

**Стек:** PHP 8.x + MySQL + Bootstrap 5 + Vanilla JS
**Инструмент разработки:** Claude Code (VS Code) — все промпты и правила ниже рассчитаны на него

---

## Быстрый старт — 6 шагов

1. Скопируй папку шаблона → переименуй под свой проект
2. Заполни `.docs/prd.md` — опиши свой продукт (есть ТЗ и скриншоты
   интерфейса? отдай их агенту через `.docs/prompts/project-init.md` —
   он сам разложит их по `prd.md` и `database.md`)
3. Заполни `.env` на основе `.env.example`
4. Настрой `config/config.php` — название проекта
5. `composer install` — подтянет PHPUnit (dev-зависимость, на прод не деплоится)
6. Запусти агента: используй промпты из `.docs/prompts/`

## Что заполнить под свой проект

### Обязательно (без этого не стартовать):

| Файл | Что сделать |
|------|------------|
| `.docs/prd.md` | Написать описание продукта, фичи |
| `.docs/database.md` | Дозаполнить под свой продукт — базовые e-commerce таблицы (users/categories/products/cart/orders/order_items/payment_logs) уже есть, добавляй только специфичные |
| `.env` | Заполнить на основе `.env.example` |
| `config/config.php` | Поменять название проекта |
| `CLAUDE.md` | Обновить раздел "О проекте" |
| `.docs/phases/_status.md` | Очистить таблицу фаз — оставить только структуру |

### Универсальные файлы — не трогать:

| Файл | Почему не трогать |
|------|------------------|
| `src/Core/*.php` | Работает для любого проекта |
| `.htaccess`, `public/.htaccess` | Редирект + `Options -Indexes` (запрет листинга директорий) |
| `public/uploads/.htaccess` | Запрещает выполнение PHP в папке загрузок — защита от RCE через подделанный тип файла. Не удалять и не ослаблять |
| `public/index.php` | Универсальный front controller |
| `.claude/rules/*.md` | Правила кода универсальны |
| `.docs/dod-global.md` | Подходит для любого PHP проекта |
| `.docs/prompts/*.md` | Промпты универсальны |
| `phpunit.xml`, `tests/bootstrap.php` | Конфиг тестов универсален |

**Про `storage/` vs `public/uploads/`:** `storage/` лежит вне document root
и по HTTP недоступна в принципе — туда идут логи, кэш, временные файлы.
`public/uploads/` — единственное место, куда можно класть контент, который
должен открываться прямой ссылкой (фото товаров), и единственное место, где
пользовательская загрузка в принципе возможна. Именно поэтому там отдельный
`.htaccess`, запрещающий исполнение PHP.

### Очистить под свой проект:

| Файл | Что очистить |
|------|-------------|
| `config/routes.php` | Убрать все маршруты кроме / и /login |
| `database/install.php` | Убрать все таблицы, оставить только структуру подключения |
| `TASK.md` | Очистить полностью |
| `.docs/dev-log.md` | Очистить записи |
| `.docs/phases/_status.md` | Очистить фазы |

## Как работать с системой — шпаргалка

### Инициализация нового проекта (один раз)
0. Есть ТЗ и/или скриншоты интерфейса → скопировать промпт из
   `.docs/prompts/project-init.md`, отправить в чат Claude Code вместе
   с ТЗ/скриншотами → агент заполняет `prd.md` и дополняет
   `database.md` → подтвердить

### Начало сессии
1. Открыть `current-pipeline.md` → найти ссылку на `_status.md`
2. Открыть `_status.md` → понять какая фаза в работе
3. Открыть `TASK.md` → прочитать что делать сегодня

### Планирование новой фазы
4. Скопировать промпт из `.docs/prompts/phase-init.md`
5. Отправить в чат Claude Code → агент предлагает план → подтвердить

### Создание таска
6. Скопировать промпт из `.docs/prompts/task-init.md`
7. Отправить в чат Claude Code → агент создаёт TASK.md → подтвердить

### Реализация
8. Сказать агенту: `Реализуй задачу из TASK.md. Следуй CLAUDE.md`
9. Агент пишет код

### Проверка
10. Проверить DoD вручную в браузере — каждый пункт из TASK.md
11. Если что-то не работает → сказать агенту конкретно что не так

### Закрытие таска
12. Поставить `[x]` в DoD в `TASK.md`
13. Обновить статус таска в `phase-N.md`
14. Если есть ещё таски → вернуться к шагу 6

### Закрытие фазы
15. Попросить агента создать отчёт: `Прочитай phase-N.md и создай phase-N-report.md`
16. Обновить `_status.md` → фаза ✅ Завершена, следующая 🔄 В работе

### Конец сессии
17. Написать в `.docs/dev-log.md`: дата, что сделал, что следующее
