# PetPark — сайт зоомагазина и центра ухода за питомцами

Демо-проект интернет-магазина и сервиса записи на услуги для «PetPark»
(Ростов-на-Дону): один сайт вместо магазина, звонка администратору и
десятка мессенджеров.

**Стек:** PHP 8.x + MySQL 8 + Bootstrap 5 + Vanilla JS (без Node.js,
без ORM, без фреймворков — подробности и обоснование в `CLAUDE.md`)

---

## Что строим

Покупатель на сайте:
- выбирает корма и аксессуары в каталоге (фильтры, поиск, варианты
  товара, скидки) и оформляет заказ с доставкой курьером или
  самовывозом;
- сам записывается на груминг или ветконсультацию — выбирает
  специалиста и свободное время, без звонка администратору;
- заводит карточки своих питомцев и видит по ним историю заказов и
  записей в личном кабинете;
- получает уведомления о статусе заказа/записи/возврата;
- может оформить возврат товара с фото.

Администратор и владелец в единой панели:
- ведут все заказы (в том числе оформленные вручную) и все записи на
  услуги;
- управляют каталогом, остатками, скидками, характеристиками товаров;
- видят специалистов, их календарь и клиентскую базу;
- смотрят финансовые отчёты (только роль «Владелец»);
- пользуются ИИ-помощниками: разбор характеристик товара из
  описания, генератор описаний, консультант в чате для покупателей,
  разбор входящих обращений в черновик заказа.

Тот же каталог с наценкой выгружается на Wildberries и Ozon.

## Что получим на выходе

Рабочий демо-сайт на shared-хостинге, полностью проходящий путь
покупателя от каталога до подтверждённого заказа и путь клиента от
выбора услуги до записи к специалисту, плюс админ-панель для
управления всем этим — без внешних сервисов, которые в демо-версии не
нужны для проверки продукта (см. ниже).

## Статус проекта: демо

Цель этого проекта — показать, как работает продукт, а не построить
готовые к продакшену интеграции с внешними сервисами. Поэтому часть
интеграций в демо-версии **не реализована** — вместо реального
обращения к внешнему сервису в админке есть страница/форма, которая
показывает, как это будет выглядеть, но данные не покидают проект и
ничего не приходит извне. Архитектура это учитывает: каждая такая
интеграция уже вынесена в свой класс/сервис в `src/Services/`, поэтому
в будущем боевую версию можно подключить, не переписывая
контроллеры и модели вокруг неё.

Не реализовано в демо-версии (заглушка в архитектуре):
- **Платёжные системы** — оплата картой на сайте
- **Мессенджеры и Avito** (MAX, Telegram, ВКонтакте, Avito) — единый
  инбокс обращений
- **AmoCRM** — статус заказа после подтверждения
- **МойСклад** — синхронизация остатков
- Дополнительно заглушками остаются выгрузка на **Wildberries/Ozon**
  и отправка **SMS** (уведомления в демо уходят на email)

Полностью реализовано, не заглушка: **ИИ-помощники** — это то, что
демо-проект действительно проверяет.

Подробности и обоснование решения — `.docs/prd.md` (раздел «О
продукте», `ADR-001`).

## Как запустить локально

1. `composer install` — подтянет PHPUnit (dev-зависимость, на прод не деплоится)
2. Скопировать `.env.example` → `.env`, заполнить подключение к MySQL,
   SMTP и `SEED_USER_PASSWORD` (≥ 8 символов, только для локального сида)
3. `php database/install.php` — создаст таблицы (идемпотентно, можно
   запускать повторно)
4. `php database/seed.php` — создаст тестовых пользователей по одному
   на каждую роль (не запускается при `APP_ENV=production`):

   | Роль | Email |
   |------|-------|
   | Владелец | `owner@petpark.test` |
   | Администратор смены | `shift-admin@petpark.test` |
   | Контент-редактор | `content-editor@petpark.test` |
   | Специалист | `specialist@petpark.test` |
   | Покупатель | `customer@petpark.test` |

   Пароль для всех — значение `SEED_USER_PASSWORD` из вашего `.env`.
5. `php database/seed-catalog.php` — демо-каталог (5 категорий с
   подкатегориями, 7 брендов, 60 товаров с Вариантами, отзывы) из
   `00-input/attachments/catalog-petpark.xlsx`; идемпотентно, требует
   `php.ini` с включённым `extension=gd` (генерация демо-фото
   товаров в `public/uploads/products/`)
6. `composer test` — юнит-тесты чистой логики (Core-хелперы, Router)
7. Document root сервера — папка `public/`

### Истечение резерва (cron)

Заказ «картой» держит резерв остатка 30 минут (`ORDER_RESERVE_MINUTES`).
Неоплаченные Заказы с истёкшим резервом отменяет скрипт — его нужно
запускать по расписанию, например раз в 5 минут:

```
*/5 * * * * php /путь/к/проекту/bin/expire-reservations.php
```

Скрипт идемпотентен и работает только из CLI; итог прогона печатает в
консоль и пишет в `storage/logs/app.log` (прогон, что-то отменивший, —
уровнем `WARNING`, пустой — `INFO`).

**Если cron на хостинге недоступен:** запускать ту же команду вручную
из SSH/панели хостинга («Выполнить команду»/планировщик заданий) или
раз в несколько минут дёргать её любым внешним планировщиком. В демо
без запуска скрипта резерв просто остаётся занятым до ручного запуска.


### Автоотмена невостребованных Заказов (cron)

Заказ в статусе «Готов к выдаче» (самовывоз) или «Передан курьеру»
дольше 3 суток (`ORDER_UNCLAIMED_DAYS`) отменяет скрипт: остаток
возвращается, оплаченный картой Заказ получает автовозврат денег.
Запускать по расписанию, например раз в час:

```
0 * * * * php /путь/к/проекту/bin/cancel-unclaimed-orders.php
```

Скрипт идемпотентен и работает только из CLI; итог прогона печатает в
консоль и пишет в `storage/logs/app.log` (прогон, что-то отменивший или
упавший, — уровнем `WARNING`, пустой — `INFO`). Код выхода 1 — на
каком-то Заказе была ошибка (смотри лог). Без cron — запускать вручную,
как `expire-reservations.php` выше.

## Как устроена разработка

Проект ведётся по фазам (`.docs/phases/_status.md`) — 10 фаз, от
фундамента (роутер, авторизация, логгер) до финальной проверки
SEO/адаптивности. Текущий таск в работе — всегда в `TASK.md`.

1. Начало сессии — открыть `.docs/phases/_status.md`, найти фазу в
   работе, затем `TASK.md`
2. Реализация — по правилам `CLAUDE.md` и `.claude/rules/*.md`, строго
   в рамках текущего таска
3. Проверка — вручную по чек-листу DoD из `TASK.md`, юнит-тестами для
   логики без БД (`composer test`)
4. Закрытие таска/фазы — отметка в `TASK.md`, обновление статуса в
   `_status.md`, запись в `.docs/dev-log.md`
